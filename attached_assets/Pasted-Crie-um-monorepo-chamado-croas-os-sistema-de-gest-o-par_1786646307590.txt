Crie um monorepo chamado "croas-os": sistema de gestão para negócio de mentoria.

STACK
- Monorepo com pnpm workspaces
- web/: Next.js 14 (App Router) + TypeScript + TailwindCSS
- api/: Node.js + Fastify + TypeScript + Prisma + PostgreSQL
- Auth: Google OAuth (NextAuth no web, validação de JWT na api)

ESTRUTURA
croas-os/
├─ web/
│  ├─ src/app/                    rotas e layouts
│  ├─ src/modules/<modulo>/       components, hooks, api, types
│  ├─ src/lib/api-client.ts       ÚNICO ponto de chamada à api (tipado)
│  └─ src/components/ui/          design system
├─ api/
│  ├─ src/modules/<modulo>/       routes, controller, service, repository, schema
│  ├─ src/core/                   auth, permissions, db, errors, config
│  └─ prisma/schema.prisma
└─ package.json                   workspaces + script "dev" sobe web e api juntos

MÓDULOS (mesmo nome nos dois lados)
auth · users · permissions · dashboard · finance · students · commercial · team · calendar

REGRAS DE INTEGRAÇÃO
- api expõe REST em /api/v1/<modulo>
- Contratos validados com Zod na api; tipos exportados e consumidos pelo web
- web nunca chama fetch direto — só via api-client.ts
- Toda rota da api passa por middleware requirePermission(modulo, 'read' | 'write')
- Erros padronizados: { error: { code, message } }

MODELO DE DADOS (Prisma)
User (role: MASTER | COLLABORATOR | CLIENT)
Permission (userId, module, level: NONE | READ | WRITE)
Student · Plan (PADRAO | PREMIUM) · Session · FormResponse · File
Task · Lead (stage) · Transaction (status: PENDING | RECONCILED) · Goal

PERFIS
- MASTER: acesso total, gerencia permissões
- COLLABORATOR: só os módulos liberados individualmente
- CLIENT: só os próprios dados, somente leitura
